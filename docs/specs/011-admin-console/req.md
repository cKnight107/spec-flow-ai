### 第一层：先做“壳”

也就是先把这些定下来：

* 路由
* 页面布局
* 菜单结构
* 权限占位
* 页面状态流转
* 组件骨架

## 你此时最该先写哪些前端页面

你这个项目我建议先分成 **两个前端应用**：

### 1. `apps/admin-console`

面向平台管理员、应用管理员、知识管理员、开发者、审计人员的控制台

优先页面：

* 控制台首页 / 仪表盘
* 应用管理列表页
* 应用详情 / 配置页
* 模型管理页
* 知识库管理页
* 工具中心页
* 工作流管理页
* Prompt / Playground 页
* 审计日志页
* 成本与观测页
* 用户 / 角色 / 权限页

因为文档里的角色和能力域，绝大多数都要通过控制台完成配置、治理和运营。 

---

## 开发顺序我建议这样排

### 第一阶段：只做页面原型，不接后端

先完成：

* 侧边栏
* 顶部导航
* 页面路由
* 统一 layout
* 表格页
* 表单页
* 详情页
* 抽屉 / 弹窗 / 状态组件

这时候用静态 JSON 就够了。

### 第二阶段：抽公共组件

先沉淀你文档里已经确定会复用的组件：

* `ChatPanel`
* `CitationPanel`
* `ConversationHistory`
* `ApprovalBanner`
* `ToolExecutionTimeline`
* `PageHeader`
* `SearchFilterBar`
* `DataTable`
* `JsonViewer`
* `StatusBadge`

这一步非常值，因为应用交付中心已经明确要求这些标准组件存在。

### 第三阶段：定义页面契约

不是先联调，而是先给每个页面写：

* 页面需要什么数据
* 查询条件是什么
* 返回结构是什么
* 哪些状态需要轮询 / SSE
* 哪些按钮是高风险操作

这一步可以先形成 `specs/` 文档，或者直接放成 `schemas/` + mock API。
