### 5. 关键决策
- 将共享存储能力拆成三个窄包规格，而不是一个统一 `storage` 包，以减少依赖耦合与职责混杂。
- `db-kit` 只承接数据库基础设施能力，不承接通用 CRUD 与业务 Repository。
- `db-kit` 首版推荐基于 `pg` + `kysely`，优先复用成熟 PostgreSQL 生态。
- `cache-kit` 聚焦 Redis 的连接、键规范、TTL、锁与测试替身。
- `cache-kit` 首版推荐基于 `ioredis`，不以通用缓存抽象层作为核心。
- `oss-kit` 聚焦对象存储通用操作与签名 URL，业务对象绑定仍留在服务内部。
