- 日期：2026-03-14

### 1. 目标
修复 `admin-console` 在 `next dev` / `next build` 过程中无法解析 `packages/shared-config` 源码导出的错误。

### 2. 输入依据
- 用户运行 `pnpm --filter @enterprise-ai-hub/admin-console dev` 报错：`Module not found: Can't resolve '../core/schema/admin-console.js'`
- 当前实现：`@enterprise-ai-hub/shared-config/public` 直接导出 workspace 内 TS 源码
- 约束：不能破坏 `shared-config` 现有对 `admin-console` 与 `model-gateway` 的接入方式

### 3. 本次改动
- 将 `packages/shared-config/src/**` 内部相对导入统一改为无扩展名形式，兼容 Next.js workspace 转译
- 调整 `services/model-gateway/tsconfig.json` 为 `moduleResolution: "Bundler"`，避免继续依赖 `.js` 扩展导入
- 修复 `packages/shared-config/src/core/fields.ts` 残留的错误导入
- 新增 `packages/shared-config/scripts/fix-dist-test-specifiers.mjs`，仅在单测编译产物阶段补齐 `.js` 扩展，保证 Node ESM 测试可执行
- 更新 `packages/shared-config/package.json` 测试脚本

### 4. 涉及文件
- `packages/shared-config/package.json`
- `packages/shared-config/scripts/fix-dist-test-specifiers.mjs`
- `packages/shared-config/src/core/fields.ts`

### 5. 关键决策
- 源码层面优先兼容 bundler，而不是继续围绕 Node ESM 的 `.js` 扩展做妥协
- Node 原生单测通过“只修测试产物”的方式兼容，不反向污染业务源码导入风格
- `next dev` 在当前沙箱中无法监听端口，因此以 `next build` 作为等价编译验证
