## [CL-025] 拆分 shared-config public 入口的前后端边界
- 日期：2026-03-14
- 任务编号：TASK-025
- Spec：`docs/specs/012-shared-config/spec.md`
- 执行方式：Codex
- 执行人：AI + Human
- 状态：Done

### 1. 目标
修复 `admin-console` 客户端组件引入共享配置后触发 `node:` 内置模块打包报错的问题。

### 2. 输入依据
- 用户在 `ConsoleLayout` 中使用 `publicConfig.NEXT_PUBLIC_CONSOLE_TITLE` 时，Next.js 构建报 `UnhandledSchemeError: node:child_process`
- 根因链路：客户端组件引入 `loadPublicConfig()`，间接依赖 `server/load-config.ts` 与 `core/env.ts`

### 3. 本次改动
- 将 `packages/shared-config/src/public/read-public-config.ts` 收敛为纯客户端安全实现，仅保留 `readPublicConfig`
- 新增 `packages/shared-config/src/public/load-public-config.ts`，承载服务端配置加载逻辑
- 新增 `@enterprise-ai-hub/shared-config/public/server` 子路径导出，供服务端组件和服务端模块使用
- `admin-console` 的 `public-config.ts` 改为服务端专用模块
- `ConsoleLayout` 改为通过 props 接收公共配置，避免客户端直接 import 服务端加载逻辑

### 4. 涉及文件
- `packages/shared-config/src/public/read-public-config.ts`
- `packages/shared-config/src/public/load-public-config.ts`
- `packages/shared-config/src/public/server.ts`
- `packages/shared-config/package.json`
- `apps/admin-console/lib/public-config.ts`
- `apps/admin-console/lib/consoleLayout.tsx`
- `apps/admin-console/app/(console)/layout.tsx`
- `docs/ai-change-log/CL-025.md`

### 5. 关键决策
- `@enterprise-ai-hub/shared-config/public` 必须保持客户端安全，不再混出服务端依赖
- 服务端加载配置单独走 `@enterprise-ai-hub/shared-config/public/server`
- 客户端组件只消费序列化后的配置对象，不自行参与配置发现和文件读取
