# 代码规范

## 通用原则
- 默认使用 TypeScript 作为实现语言
- 优先小步增量修改，避免一次性跨多个能力域重写
- 先有规格再有实现，禁止脱离 `docs/specs/` 直接扩写复杂功能

## 目录与文件
- `apps/` 仅放用户入口、BFF 和前端应用
- `services/` 仅放平台服务，不直接耦合具体前端页面
- `packages/` 只放共享类型、SDK、Schema、测试工具与通用库
- `integrations/` 只放外部系统适配，不承载核心业务决策
- 文件命名优先使用 kebab-case；TypeScript 类型、类、接口使用 PascalCase

## TypeScript 约束
- 开启 `strict`，不得通过关闭类型检查规避问题
- 禁止滥用 `any`；确有必要时必须说明原因并尽量收敛范围
- 输入输出协议优先定义在 `dto`、`shared-types` 或 `schema` 中
- 跨服务共享字段必须通过 `packages/` 统一定义，禁止复制粘贴协议

## 配置与常量
- 环境差异配置放在 `.env`、`configs/` 或服务配置模块
- 禁止在业务代码中硬编码模型 ID、路由策略、权限规则和外部系统地址
- 可版本化策略优先落库前先落仓到 `configs/`

## 日志与可观测
- 关键链路必须带 `trace_id`、`tenant_id`、`app_id` 等上下文字段
- 禁止输出明文密钥、敏感个人信息与完整凭据
- 错误日志必须包含足够定位信息，但不能泄露受保护数据

## 文档同步
- 新增模块时同步补 `README.md`
- 影响架构边界、接口契约或交付方式的改动，必须同步更新 `docs/`
