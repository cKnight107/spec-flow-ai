# 样式规范

## 首选方案
- 页面和组件样式优先使用 Tailwind CSS。
- 需要复用的视觉变量应沉淀为设计 token 或主题变量，避免直接写死颜色和间距。

## less 使用
- 只有在以下场景下才使用 `.less`：
  - 现有存量页面已基于 less
  - Tailwind 难以表达的大段复杂样式
  - 第三方组件覆盖样式需要集中管理
- less 文件命名使用 `kebab-case`，并按页面或组件就近放置。

## 约束
- 禁止在 JSX 中堆叠难以维护的超长 class 字符串，必要时抽成常量或组件。
- 禁止把业务逻辑写进样式文件。
- 样式改动要兼顾桌面端与移动端表现。
