# 测试与质量约束

## 测试分层
- `tests/contract`：接口契约与 schema 一致性
- `tests/integration`：服务间联调与外部依赖集成
- `tests/e2e`：关键用户链路
- `tests/performance`：性能基线与容量验证

## 最低要求
- 新增接口必须至少补充契约测试或单元测试
- 新增跨服务流程必须补充集成测试
- 涉及权限、审批、审计、成本统计的改动必须覆盖异常流
- 修复缺陷时必须增加可复现该缺陷的测试

## 验证重点
- 权限继承是否正确
- 检索结果是否带引用与权限过滤
- 模型调用是否记录 usage、cost 和 trace
- 工具调用是否记录审批和审计事件

## 交付门槛
- 无法验证的改动必须明确记录风险
- 发布前至少完成人工链路检查
- 重要模块的测试用例应在对应 `docs/specs/*/test-cases.md` 中可追溯
