# 注释规范

## 基本原则
- 注释用于解释“为什么”，不是重复“做了什么”。
- 一眼可读的代码不要加噪音注释。
- 过期注释必须和代码一起清理。

## JSDoc
- 对外导出的复杂函数、公共工具、共享 hooks、SDK 方法建议补 JSDoc。
- JSDoc 至少说明用途、关键参数、返回值和副作用。

## 文件头注释
- 复杂规则文件、生成文件、约束强的服务入口可增加文件头注释。
- 文件头可使用以下标签：
  - `@ai-context`：说明该文件的业务上下文和所在边界
  - `@ai-rules`：说明修改该文件时必须遵守的局部规则

## 示例
```ts
/**
 * @ai-context 模型网关统一入口，负责路由、审计和成本统计。
 * @ai-rules 禁止在此处直接引入厂商 SDK，provider 适配必须下沉到 integrations。
 */
```

## 禁止项
- 禁止保留大段注释掉的旧代码。
- 禁止使用“临时修复”“不知道为什么能跑”之类无法维护的注释。
